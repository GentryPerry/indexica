# JAM conventions (repo: indexica)

The app is called JAM (renamed from Indexica on Nov 17, 2026). Storage keys keep the `ix_` prefix so saved boards carry over.

- No emojis anywhere in UI or code. Use color coding for state.
- Every board object has a stable `id`. All edits go through `History.commit()` so they are undoable and saved.
- Keep pure logic (geometry, history, model) out of `src/app.ts`, typed, and covered by tests in `tests/`.
- `src/app.ts` is the ported prototype UI and is excluded from type-checking. When touching a part of it substantially, move that part into its own typed module.
- The build must stay a single self-contained `dist/index.html` (it is also published as a Claude artifact). Do not add runtime network dependencies other than Google Fonts.
- Canvas content uses only the system font stacks in `FONTS` (`types.ts`) so exports match the screen. Do not add web fonts to canvas content.
- Before committing: `npm test` and `npm run build` must pass.
- UI follows MUI Joy UI's default theme (restyled Nov 17 from the MUI for Figma Joy UI kit; values taken from `@mui/joy`): Inter for UI text (Bricolage Grotesque only for the JAM wordmark), Joy grey and blue scales, radii 6/8/12/16 (`--r1..--r4`), Joy shadow levels (`--sh-xs/sm/md/lg`), Joy variants: plain for icon buttons and rows, soft (`--field`, hover `--soft-hi`) for secondary buttons, soft primary (`--picked` with `--accent-soft` text) for selection, solid primary (`--accent-fill`) for main actions, outlined (`--border`, `--surface`, xs shadow, 2px primary focus ring) for fields and menus. Docked outline (240px) and properties (264px) panels, tools in a floating tray. Floating pieces get `--float`; lifted cards get `--lift` only while lifted. All values are tokens at the top of `src/styles.css` with the component layer at the end; use them rather than new values.
- Signature motif: index cards and tabbed folders. Projects have a tab color (`projectColor` in `library.ts`) shown as a tab above board cards, a dot in the sidebar, and on folder art. Group labels are Joy list subheaders: 11px uppercase, 600 weight, 0.1em tracking. Menus may show icon tiles (`popupAt` item `[label, fn, cls, iconPath]`, `{ head }` for a group label).
- Board colors go through `src/palette.ts` (OKLCH): stored colors are painted per theme, outlines derive from fills, text picks readable ink. Exports always use the light look.
- Presentations: a slide is a frame with a `slide` number (deck order per page) plus optional `notes`, background `fill`, `theme`, `layout`, and `foot` (number, date, text, drawn with the slide, not board pieces). Deck order lives in `src/slides.ts`; themes, layouts, and placeholders in `src/deck.ts` (from DeckCraft, credited in the shortcuts sheet and the HTML comment). Pieces keep plain colors; `tc` links a field to a theme slot or font role and `applyTheme` repaints only fields still holding their slot's value. A page's theme is its first slide's. Placeholders are text with `ph` and `va`: fixed box, shrink-to-fit (`fitPlaceholder`, stored as `fit`), a prompt while empty (never exported), and a click on an empty one starts typing (or picks a picture). Slides always render in the light look, clipped to the frame, including on the dark canvas. Text paragraphs (`src/richtext.ts`): levels are leading tabs in the plain text, plus `bullets` ('disc' or 'num'), `lsp` (line spacing), `psp` (space above paragraphs); `layoutText` in `geometry.ts` places the lines (body placeholders step type down by level), and text pieces edit in the contenteditable paragraph editor (`src/richedit.ts`, `#red`), other pieces in the `#ed` textarea. Formatting on part of a text (text pieces, sticky notes, rectangles, ellipses, diamonds, preset shapes, and table cells, which all edit in the paragraph editor; `RICH_TYPES`): `runs` (`src/runs.ts`) are character ranges of the plain text (tabs and line breaks counted) with overrides `w`, `i`, `u`, `x` (strike), `c`, `z` (size, scaled with shrink-to-fit), `f` (font key); keep them normalized (`normRuns`), remap them when text changes outside the editor (`editRuns`, `reindentRuns` for indenting), and drop a key from them when the whole piece sets that style (`wholeStyle`). Table cells keep theirs in `cruns` (by row and column like `cells`; `edSource`/`readEditor` pick the cell being edited). `layoutText` splits styled lines into `segs`, drawn one text node per stretch (`segNodes`; `runBlock` places them in notes, shapes, and cells, and `boxTextHeight` measures them for fitting). The editor reads runs back from what the browser shows (`readRichRuns`); the format bar (`#fmt`, `placeFmt`) uses the browser's bold, italic, underline, and strike commands and applies color, size (`data-z` spans), and clearing through `applyStyle` (`fmtModel`). PowerPoint writes one `a:r` per stretch and reads every run back (a paragraph's own size is its most common one). Slide tables take a style (`tstyle`, `TABLE_KINDS` and `cellLook` in `table.ts`, DeckCraft's looks generated from one accent `tacc`, theme-linked through `tc`) with `header`, `band`, `firstCol`, `lastRow`; unstyled tables keep the board card look. Pictures (`src/picture.ts`) show a window of their image (`crop` fractions per side, the whole image stays put while cropping), with `rad`/`oval`, a border (`stroke`, `sw`), and adjustments (`bright`, `contrast`, `sat`, `gray`) as an SVG filter; double-click a picture to crop. Preset shapes (Shapes tool, U): a `rect` with `preset` (one of the 187 ECMA-376 shapes) and `adj` (adjust values that differ from the defaults), evaluated by `src/presetgeom.ts` from `data/presetShapeDefinitions.xml`, which `scripts/embed-presets.mjs` packs into `src/presets-data.ts` (generated; do not hand-edit). Each preset path fills and outlines on its own; the text sits in the preset's text box; diamond handles (`adj-i`) drag adjust values through `dragHandle`; `outlineOf` gives booleans and Convert to vector the real outline. Charts (Chart tool, J): a `chart` piece with `chart` data (`src/chart.ts`: kind, categories, series, title, legend, labels, gridlines, `xTitle`/`yTitle` axis titles by position); kinds include scatter (categories are X values, `xValues` falls back to 1, 2, 3 for named ones), radar, filled radar, and combo (columns with the last series as a line); `chartLayout` turns it into plain marks, colored from the page theme's accents (`accents` in the render context, part of the chart's draw signature); the panel edits the data table, and pasting spreadsheet rows into a cell replaces it. PowerPoint files: `src/pptx-write.ts` (Export, PowerPoint) writes the page's slides as .pptx (presets as `prstGeom` with their `adj`, text with levels and bullets, pictures with `srcRect`, tables, charts with literal data, notes, footers, the deck theme); `src/pptx-read.ts` (New slide menu, Open a PowerPoint file, or drop a .pptx on the canvas) reads slides, master and layout decoration, placeholders with inherited boxes and styles, theme colors with their modifiers, groups, connectors, pictures, tables, charts from cached values, backgrounds, and notes onto a new page; unsupported objects become labeled boxes. Both use `src/zip.ts` (browser deflate streams, no libraries) and `src/xml.ts`. `tests/fixtures/sample.pptx` was made with python-pptx. Empty content placeholders offer Insert table, chart, and picture buttons (`data-ph-act`, never exported); placeholder pictures fill their box.
- Vectors: a `path` element stores Bezier subpaths in its own box (`vw` by `vh`), drawn stretched to `w` by `h`. Path math lives in `src/vector.ts`, booleans and outline stroke in `src/boolean.ts` (polygon-clipping), brushes and the stroke eraser in `src/brush.ts` (perfect-freehand), gradients and stacked fills and strokes in `src/paint.ts`. A mask is a piece with `masking: true`; pieces with `mask: id` are clipped to its outline. Booleans are live (`src/livebool.ts`): the result is a `path` with `live: op`, its operands keep their own data with `boolIn: resultId`, are not drawn, and share the result's group; `syncLive` recomputes results in `draw()`. Commands and the panel read the selection through `panelEls()` so a boolean acts as one piece; Flatten bakes, Ungroup releases. Gradients carry optional `from`/`to` (linear) or `center`/`radius` (radial) in box fractions, dragged on the canvas (`gradTarget`/`gradMarks`); `profile` gives vector strokes a tapered width (`profileOutline` in `brush.ts`); the eraser cuts vectors through `src/vecerase.ts`. Simplify, Smooth, and Offset adjust live through one preview (`adjBegin`/`adjApply`/`adjEnd`) that commits once.
- Exact vector ops: VectorCraft's path engine is built in as gzipped wasm (`wasm/`, `src/ixops-wasm.ts` generated by `scripts/embed-wasm.mjs`), loaded by `src/pathops.ts` and wrapped in subpath terms by `src/exact.ts`. Booleans, outline stroke, offset, simplify, and smooth try it first and fall back to `boolean.ts` when it is not loaded. Engine tools live in the one Vector panel section and the right-click menu like any other command; no separate engine section or engine branding in the UI (credit sits in the shortcuts sheet and an HTML comment with the MIT notice). Keep `wasm/NOTICE`; do not hand-edit `src/ixops-wasm.ts`.
- Checklists: a list style (`bullets: 'check'`, next to 'disc' and 'num') for text pieces and sticky notes; `checked` holds the checked-off paragraph indexes (`toggleChecked`, `isChecked`, `clampChecked` in `richtext.ts`). Boxes are drawn as SVG shapes (`checkBox` in `render.ts`, never a character) with a `data-chk` hit square that toggles on one click without selecting; checked lines are struck through at half opacity. In the editor, CSS draws the box from `data-chk`/`data-done` on each paragraph, `toggleAt` handles clicks on it, and `readChecked` reads the state back (an empty paragraph never stays checked). Enter adds the next item, Tab indents (in a note with a list, Tab indents instead of adding the next note), Enter on an empty indented item steps out, Ctrl+Shift+9 toggles the style. PowerPoint gets Wingdings box bullets.
- Sticky notes work like FigJam's: square by default (`STICKY_SIDE`), text auto-fits by shrinking through `STICKY_SIZES` (`fitSticky` in `geometry.ts`, stored as `fit`) unless a size is set by hand, Wide doubles the width, and the author is stored as an opaque user id (`author`) with names looked up at render (`Store.names`), never stored. Hover outlines come from `hoverAt`/`hoverMark`; operands of a boolean keep their text drawn over the result.
- Cloudflare deployment (jam.gentryperry.com, `wrangler.toml`): static assets plus `worker/` (`/api/*` only). Cloudflare Access with Google gates the site; the Worker verifies the Access JWT (`worker/access.ts`) and stores each person's documents in D1 (`worker/api.ts`, table `docs(user, id, data, updated)`). `Store` uses it as `where: 'site'` (same-origin, no other network); the single-file build and artifact behavior are unchanged.
- Canvas drawing (`drawEls` in app.ts) keeps each piece's SVG node with a signature (its JSON plus what it depends on: connector ends, mask, frame under text, loaded picture, author name, zoom for frames) and reuses it when unchanged; pieces outside the view are skipped; far zoom drops paper shadows (below 35%) and text (below 16%). Anything new a piece's drawing reads from outside itself must be added to that signature. Use `cvBox()` rather than measuring the canvas. Big boards: `contentCache()` keeps the piece list, drawing order, and a grid index (`GridIndex` in `src/lod.ts`) until `editVer` changes (bumped by `commit`, undo, and paste; the piece count catches uncommitted adds), and `piecesIn(box)` culls through it while treating moving pieces (`movingIds`) as live. Below `LOD_ZOOM` (25%) the board draws into the `#lod` canvas as simplified pieces (`drawFar`), reused as one picture during pan and zoom and redrawn when the pointer rests; picking there goes through `pickAt`. Pan and zoom events redraw once per frame (`drawSoon`). The minimap paints into a bitmap and rebuilds only on edits; long outlines (over 400 rows) render only the rows in view; drags commit with `commitIds` so only the moved pieces are diffed.
- Phones and tablets: up to 1100px wide the outline is a drawer (`.board.ol-open`) opened from the floating `.mbar` (which also holds undo and redo); on phones (760px wide or less, or a short touch screen held sideways) the properties are a bottom sheet (`.board.pr-open`, a side sheet in landscape), toggled through `sidePanel()`. Touch on the canvas goes through `canvasDown/Move/Up` before the mouse handlers: two fingers pan and pinch (`src/touch.ts`, `pinchCam`), a second finger undoes what the first started (`History.revert`), a finger on empty space pans and a tap there clears the selection, a held finger opens the context menu on a piece (`longPress`) or, on empty space, arms box-select (move to draw the box, lift for the menu), a floating bar over the selection gives Edit, Duplicate, Delete, and More (`placeSelBar`, `#selbar`), and small handles get invisible hit rings (`touchTargets`) while `touchUI` is on. Coarse pointers get 40px+ targets in the CSS layer at the end of `styles.css`.
- Chrome stays neutral. Color belongs to board content, task status, and the Joy primary accent #0B6BCB.
